# MultiService Process Dashboard

A self-hosted platform for running and managing microservices. Provides Microsoft M365 login, a service registry, an API gateway, role-based access control, and Docker orchestration — all from a single dashboard.

---

## What's in this repo

```
rmsb-dashboard/
├── frontend/               ← React + TypeScript + Vite (login shell, dashboard, settings, users)
├── api-gateway/            ← Express API gateway (registry, users, Graph proxy, service routing)
├── docker-compose.yml      ← Auto-managed by the dashboard — do not edit manually
├── .env.example            ← Copy to .env and fill in values before first run
├── Jenkinsfile             ← Jenkins CI/CD pipeline (see docs/jenkins-setup.md)
├── .github/workflows/
│   ├── ci.yml              ← Build + push Docker images to GHCR
│   └── deploy.yml          ← SSH deploy to Oracle VM after CI succeeds
└── docs/
    ├── server-setup.md         ← VM provisioning, nginx, SSL (acme.sh + DuckDNS)
    ├── github-actions-setup.md ← GitHub Actions environment, secrets, variables
    ├── jenkins-setup.md        ← Jenkins pipeline setup
    └── switching-ci.md         ← How to toggle between GitHub Actions and Jenkins
```

## Architecture

```
Browser
  └── nginx (SSL termination)
        └── gateway :8080
              ├── /api/registry  ← service registry CRUD
              ├── /api/users     ← platform user management
              ├── /api/graph     ← Microsoft Graph proxy (org users)
              ├── /s1/*          ← proxied to s1 container (strips prefix)
              ├── /s2/*          ← proxied to s2 container (strips prefix)
              └── /*             ← dashboard frontend :5173
```

- All services share one PostgreSQL instance, each with its own schema and DB user
- Services are served at subdirectory paths — no extra ports exposed
- M365 login via MSAL — session shared across all services via localStorage
- `docker-compose.yml` is auto-generated by the gateway on service activation

## Roles

| Role | Access |
|------|--------|
| **SuperAdmin** | Everything — manage users, services, settings |
| **Admin** | Settings + Users (read-only) |
| **Viewer** | Dashboard only |

SuperAdmin emails are set via `ADMIN_EMAILS` in `.env`.

## Local Development

```bash
git clone https://github.com/SairaNawaz/rmsb-dashboard.git
cd rmsb-dashboard
cp .env.example .env
# fill in .env values

# Start postgres
docker compose up postgres -d

# Install and run
npm install
npm run dev   # frontend on :5173, gateway on :8080
```

## Adding a New Service

1. Use [rmsb-service-template](https://github.com/SairaNawaz/rmsb-service-template) to create a new repo
2. Follow the template README to wire up your stack
3. Register the service via the dashboard Settings page
4. Push to main — CI builds the image, CD deploys it
