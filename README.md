# RMSB Dashboard

The central platform hub for RMSB. Provides Microsoft M365 login, a service registry, API gateway, role-based access control, and Docker orchestration for all microservices.

---

## What's in this repo

```
rmsb-dashboard/
├── frontend/          ← Login shell + Dashboard + Settings + Users (React + TypeScript + Vite)
├── api-gateway/       ← Express API gateway — registry, users, Graph proxy, service routing
├── docker-compose.yml ← Auto-generated by Sync Compose — do not edit manually
├── .env.example       ← Copy to .env before first run
└── .github/workflows/
    ├── ci.yml         ← Build + push Docker images to GHCR
    └── deploy.yml     ← SSH deploy to Oracle VM after CI succeeds
```

---

## Roles

| Role | Access |
|------|--------|
| **SuperAdmin** | Everything — manage users, services, settings |
| **Admin** | Settings + Users (read-only) |
| **Viewer** | Dashboard only |

SuperAdmin emails are set via `ADMIN_EMAILS` in `.env`. All other users are assigned roles from the Users page or default to Viewer on first login.

## Server Setup (Oracle Cloud VM)

### 1. Provision VM

- Shape: `VM.Standard.A1.Flex` (Always Free ARM — 4 OCPU, 24 GB RAM)
- OS: Ubuntu 22.04
- Open ports in Security List: `22` (SSH), `80` (HTTP), `443` (HTTPS)

### 2. SSH into the VM

```bash
chmod 400 /path/to/private-key.key
ssh -i /path/to/private-key.key ubuntu@<PUBLIC_IP>
```

### 3. Install Docker

```bash
sudo apt update && sudo apt install -y docker.io docker-compose-plugin
sudo usermod -aG docker $USER
newgrp docker
```

### 4. Open firewall ports

```bash
sudo iptables -I INPUT -p tcp --dport 80 -j ACCEPT
sudo iptables -I INPUT -p tcp --dport 443 -j ACCEPT
sudo iptables -I INPUT -p tcp --dport 8080 -j ACCEPT
sudo netfilter-persistent save
```

### 5. Install nginx + SSL

```bash
sudo apt install -y nginx certbot python3-certbot-nginx
sudo certbot --nginx -d your-domain.com
```

### 6. Configure nginx

Edit `/etc/nginx/sites-enabled/default` — replace all location blocks with a single rule that routes everything through the gateway:

```nginx
server {
    listen 443 ssl;
    server_name your-domain.com;

    ssl_certificate /etc/letsencrypt/live/your-domain.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/your-domain.com/privkey.pem;

    location / {
        proxy_pass http://localhost:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}

server {
    listen 80;
    server_name your-domain.com;
    return 301 https://$host$request_uri;
}
```

```bash
sudo nginx -t && sudo systemctl reload nginx
```

### 7. Clone repo and configure

```bash
git clone https://github.com/SairaNawaz/rmsb-dashboard.git
cd rmsb-dashboard
cp .env.example .env
nano .env   # fill in all values — see Environment Variables section below
```

### 8. Start the platform

```bash
docker compose pull
docker compose up -d
```

### 9. Set yourself as SuperAdmin

```bash
docker exec -it rmsb-postgres psql -U admin -d rmsb_db \
  -c "INSERT INTO platform_users (email, display_name, role) \
      VALUES ('you@company.com', 'Your Name', 'SuperAdmin') \
      ON CONFLICT (email) DO UPDATE SET role = 'SuperAdmin';"
```

## GitHub Actions Setup

### CI (build + push images)

Add these secrets to the `rmsb-dashboard` repo:

| Secret | Value |
|--------|-------|
| `VITE_ADMIN_EMAILS` | Comma-separated SuperAdmin emails |

### CD (auto-deploy to VM)

| Secret | Value |
|--------|-------|
| `VM_HOST` | VM public IP |
| `VM_USER` | `ubuntu` |
| `VM_SSH_KEY` | Contents of your private SSH key |

### Auto-deploy from service repos

Each service repo needs one secret:

| Secret | Value |
|--------|-------|
| `DEPLOY_PAT` | Fine-grained PAT with **Contents: read+write** on `rmsb-dashboard` |

## Adding a New Service

### 1. Create from template

Go to [rmsb-service-template](https://github.com/SairaNawaz/rmsb-service-template) → **Use this template** → create your repo.

### 2. Update the template TODOs

See the template README for the full list. Minimum changes:
- `SERVICE_NAME` in `ci.yml` and `src/index.js`
- `VITE_SERVICE_BASE` in `Dockerfile`, `ci.yml`, `vite.config.ts`, `main.tsx`
- `SERVICE_DISPLAY_NAME` in `Layout.tsx`
- Replace `src/routes/items.js` and `src/db/migrate.js` with your service logic
- Replace `frontend/src/pages/Home.tsx` with your main page

### 3. Add DEPLOY_PAT secret to the new repo

Settings → Secrets → Actions → New secret → `DEPLOY_PAT`

### 4. Register on the dashboard

1. Log in at `https://your-domain.com` → **Settings**
2. Click **Register Service**, fill in:
   - **Service ID**: short name matching `SERVICE_NAME` (e.g. `s2`)
   - **Display Name**: shown on dashboard card (e.g. `Capacity Planning`)
   - **Port**: container port from your Dockerfile (e.g. `3002`)
   - Other fields are auto-filled
3. Click **Activate**
4. Click **Sync Compose** — regenerates `docker-compose.yml` and triggers auto-deploy

### 5. Push to main

CI builds the image → pushes to GHCR → triggers dashboard deploy → service goes live.

## Architecture

```
Browser
  └── nginx (SSL termination)
        └── gateway :8080
              ├── /api/registry  ← service registry CRUD
              ├── /api/users     ← platform user management
              ├── /api/graph     ← Microsoft Graph proxy (org users)
              ├── /s1/*          ← proxied to s1 container (strips prefix)
              ├── /s2/*          ← proxied to s2 container (strips prefix)
              └── /*             ← dashboard frontend container :5173
```

- All services share one PostgreSQL instance, each with its own schema
- Services are served at subdirectory paths — no extra ports exposed
- M365 login via MSAL — session shared across all services via localStorage
- `docker-compose.yml` is auto-generated by Sync Compose — never edit manually
